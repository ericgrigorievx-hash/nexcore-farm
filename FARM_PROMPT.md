# Конвейер ежедневного запуска

Этот файл — инструкция для каждого запуска фермы. Меняй его, чтобы менять поведение
агента: запланированная задача просто говорит «выполни FARM_PROMPT.md».

## 0. Подготовка
- Склонируй репо, прочитай `CLAUDE.md` целиком — это закон.
- `git pull`, убедись, что main чистый.

## 1. Выбор задачи
- Возьми первую `[ ]` из `BACKLOG.md`. Нет таких → напиши отчёт «бэклог пуст» и закончи.
- Поставь ей `[~]`, закоммить `chore: start <slug>` и запушь сразу (чтобы параллельный запуск её не взял).

## 2. Спека (≤ 10 минут)
- `projects/<slug>/SPEC.md`: пользовательские сценарии, команды/кнопки, модель данных, что НЕ делаем.
- Сценарии из спеки = список тестов, которые ты напишешь.

## 3. Код
- `cp -r templates/aiogram-bot projects/<slug>`, переименуй под проект.
- Логику держи в чистых функциях / сервисах (`bot/services/`), хендлеры тонкие — так тестировать проще.
- БД — через `bot/db.py` из шаблона, схема в константе `SCHEMA`.
- Роутеры — только фабрикой `create_router()` (как в `bot/handlers.py`), иначе тесты упадут с «Router is already attached».
- Тесты пиши через офлайн-стенд `env` из `tests/conftest.py`: настоящий Dispatcher, Telegram API подменён.

## 4. Тесты — ворота
```
cd projects/<slug>
pip install -r requirements.txt -r requirements-dev.txt --break-system-packages -q
python -m pytest -q
python -m scripts.smoke
```
- Красное → чини. Максимум **3 цикла** «починил → перепрогнал».
- После 3 циклов всё ещё красное → ветка `wip/<slug>`, статус `[!]`, в отчёт — какой тест падает и почему.

## 5. Самопроверка
Перед пушем перечитай диф глазами ревьюера: секреты? `print` с токенами? захардкоженные ID? незакрытые TODO?
Пройди сценарии из SPEC.md и сверь с тестами — каждый сценарий покрыт?

## 6. Пуш
- Зелёное → коммит `feat(<slug>): <что сделано>` в main, статус `[x]`, перенеси строку в «Готово».
- Railway автоматически деплоит обновления уже подключённых проектов.
- Новому проекту нужен сервис на Railway — его один раз создаёт Эрик. Напиши в отчёте готовую инструкцию:
  Root Directory, Start Command, список переменных окружения.

## 6.5 Промо-кит (только для `[x]`)
Папка `projects/<slug>/promo/`, всё на русском, без выдуманных цифр и отзывов:
- `botfather.md` — имя бота, 3 варианта @username, About (≤120 символов), Description (≤512), список команд для /setcommands.
- `posts.md` — 3 поста для Telegram-каналов под разные заходы: «боль → решение», «фича-демо», «короткий тизер». Каждый ≤ 600 символов, с призывом и местом под ссылку `{BOT_LINK}`.
- `pitch.md` — личное сообщение админу тематического канала: кто мы, чем бот полезен его аудитории, что предлагаем (бартер/оплата). 2 варианта: короткий и подробный.
- `channels.md` — 5–10 типов каналов/чатов, где сидит целевая аудитория, и почему (без выдуманных названий и цифр подписчиков; конкретные каналы — только если они известны из задачи).
- `b2b.md` — если бот для бизнеса: короткое коммерческое предложение владельцу (что получает, как подключить).
Ничего не публикуй и никому не пиши сам — только готовые тексты. Публикацию делает Эрик.

## 7. Отчёт
`reports/YYYY-MM-DD.md` (если файл есть — допиши секцию) и закоммить вместе с остальным:
```
## <slug> — ✅ готово / ⚠️ wip / ❓ вопрос
Что сделано: 2–4 строки
Тесты: N passed, M failed
Деплой: автодеплой / нужен новый сервис (инструкция ниже) / не деплоилось
Что проверить руками: 1–3 пункта
Промо: готово в promo/ — лучший пост целиком прямо в отчёте
Следующий шаг: …
```
Последнее сообщение запуска — этот же отчёт коротко, чтобы он пришёл уведомлением.
