# sat-tasks-shop — спека

Бот-витрина SAT Math заданий по темам для репетиторов: каталог тем → карточка темы → превью →
«Запросить пакет» (заявка уходит админу). Оплаты нет — админ договаривается с репетитором сам.

## Что переиспользуем
| Откуда | Что берём | Как адаптируем |
|---|---|---|
| `templates/aiogram-bot` | каркас: config, db, офлайн-стенд тестов, smoke, Procfile/railway.json | расширили `bot/testing.py` (колбэки, документы) |
| Комп: `Projects/OGE Math Bot/.../app` | `handlers/admin.py` + `services/admin_service.py`: проверка админа по списку ID из env, `/admin` с метриками; модель `Task` с `is_active` (мягкое скрытие вместо удаления) и upsert по ключу источника; раскладка inline-меню из `keyboards/main.py` | SQLAlchemy+alembic → aiosqlite с `SCHEMA`; метрики оплат/пробников выкинуты (платежей нет); upsert по коду темы; глобальные роутеры → фабрики `create_router()` |
| Комп: `Workspace/SAT` (19 тем, 4 раздела) | коды тем, названия, число заданий в каждом PDF (`Zadaniya_1-N.pdf`) | зашиты в `bot/services/catalog.py` как сид `SAT_TOPICS`, загружается командой `/seed_sat`. **PDF в git не кладём** — превью и пакеты админ заливает через бота |
| Пишем заново | заявки (таблица `requests`, уведомление админов, кнопки «выполнено/отклонить»), превью по `file_id`, разделы | — |

Секреты/ID из донора не переносились: токен и админы — только через переменные окружения.

## Сценарии (= тесты)
Пользователь (репетитор):
1. `/start` — приветствие + меню (Каталог, Мои заявки); юзер сохраняется в БД.
2. Каталог → список разделов (только с активными темами, с числом тем).
3. Раздел → список тем с количеством заданий.
4. Тема → карточка: название, раздел, число заданий, кнопки «Превью» и «Запросить пакет».
5. Превью: если админ загрузил — бот шлёт файл (документ или фото); если нет — «превью скоро».
6. «Запросить пакет» → заявка `new`, пользователю подтверждение, всем админам — сообщение с кнопками.
7. Повторный запрос той же темы, пока прошлая заявка `new`, — новая не создаётся, бот напоминает.
8. Скрытую тему нельзя открыть/запросить.
9. `/my` — мои заявки со статусами.

Админ:
10. `/seed_sat` — загружает 19 тем SAT (повторный вызов не дублирует, превью не стирает).
11. `/addtopic CODE | Раздел | Название | Кол-во` — создать/обновить тему; ошибки формата — подсказка.
12. Документ/фото с подписью `/preview CODE` — превью темы.
13. `/hide CODE`, `/show CODE` — скрыть/вернуть тему.
14. `/requests` — новые заявки с кнопками; «✅ Выполнено» / «✖️ Отклонить» меняет статус и уведомляет репетитора.
15. `/admin` — метрики: пользователи, темы (активные/всего), заявки (новые/всего) + шпаргалка команд.
16. Все админ-команды для не-админа — «только для админов».

## Модель данных
- `users(id, username, created_at)` — из шаблона
- `sections(id, title UNIQUE, sort)`
- `topics(code PK, section_id, title, tasks_count, preview_file_id, preview_kind, is_active, sort)`
- `requests(id, user_id, username, first_name, topic_code, status new|done|rejected, created_at, closed_at)`

## Что НЕ делаем
- Оплату (донор умеет, но в задаче «без оплаты пока»; см. правило 5 — никаких рандом-механик).
- Автоматическую выдачу PDF-пакетов — пакет отправляет админ вручную после договорённости.
- Хранение PDF в репозитории.
